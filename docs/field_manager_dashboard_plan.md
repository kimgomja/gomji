# 현장 관리자용 안전 대시보드 제품 기획안

작성: 2026-10-03 · 상태: 첫 설계안 · 대상: 산업현장 관리자 / 작업반장 / 안전관리자

기존 Streamlit 화면과 코드는 [`archive/dashboard_2026-10-03`](../archive/dashboard_2026-10-03/SNAPSHOT.md)에 보존했다. 새 화면은 기존의 회색 바깥 배경, 중앙 대시보드 프레임, 왼쪽 내비게이션, Pretendard, 절제된 포인트 색상과 정교한 인포그래픽을 이어간다.

## 현재 구현 상태 (2026-10-04)

빈 일정 날짜에서는 계획표와 현장 일정을 대조한 확인자·시각을 남길 수 있다. 이 기록은 계획표에 해당 날짜의 작업이 등록되지 않았음을 확인한 내용이며, 실제 현장의 무작업이나 안전 승인을 뜻하지 않는다. 날짜별 계획이 변경되면 확인을 다시 요구하고 JSON 백업에 포함한다. 날씨와 작업 관련 확인 문구는 일정이 없는 선택일에도 표시한다.

기본 메뉴 `오늘의 작업`에 `.xlsx` 계획서 업로드·원문 행 미리보기·적용, 날짜별 일정, 시간대 그래프, 같은 구역의 겹치는 시간 후보, 시작 전 확인 목록, 일회성 빠른 등록, 작업별 현장 확인 기록을 연결했다. 샘플 외에 흔한 열 이름을 허용하고 작업ID가 없는 행에는 내용 기반 식별자를 만든다. 수정본 업로드 시 추가·변경·제외 작업과 변경 필드를 보여주며, 내용이 같은 작업의 확인 기록만 유지한다. 계획 시작일이 미래여도 처음에는 오늘을 열고, 일정이 없으면 다음 작업일로 가는 바로가기를 제공한다. 날짜와 이벤트 시각은 서버 시간대와 관계없이 KST로 계산한다. 별도 `조치 현황` 화면에서 담당자·기한별 조치를 관리하고 완료·재개 이력을 남긴다. 계획 변경은 해당 작업의 완료 조치를 재확인 상태로 되돌린다. `TBM 브리핑` 화면은 날짜별 작업·동시 작업·남은 조치·현장 예보를 모아 인쇄용 HTML과 복사 가능한 작업자 공유 텍스트를 만들고, 모든 작업의 현장 확인이 끝난 뒤 관리자 확인 기록을 남긴다. 계획·조치·검토·예보·해당 날짜의 계획 변경 이력이 바뀌면 확인본을 이전 내용으로 표시한다. 실제 TBM 진행자·참석 인원·질문과 변경 사항도 기록할 수 있다. `사고 기록 경향` 화면은 실제 사고 CSV를 연결한 경우에만 요일·월·계절별 날짜 기준 기록 건수를 보여주며, 수집 기간과 기록 수가 충분한 상황에서 두드러진 시기의 건수를 검토 메시지로 안내한다. 계절은 달력상 월 구분이며, 발생률이나 위험 순위는 계산하지 않는다. 날씨와 사고 당시의 관계는 별도 기상 관측 자료가 없어 분석하지 않는다. 계획·확인 기록·조치·TBM 이력·예보 위치는 JSON으로 내보내고 복원할 수 있다. 챗봇 별도 페이지에서 오늘 주의사항, 선택일 작업, 조치, TBM 준비 상태, 최근 계획 변경을 현재 계획에 근거해 바로 답한다. 작업계획서의 한 작업을 질문 맥락으로 사용하거나 오늘의 작업에 추가할 수 있다. 지역의 월별·계절별 사고 기록 수를 답하되, 날씨와 사고의 인과·상관관계는 추정하지 않는다. 로컬 SANUP-P 전처리 파일이 있을 때는 선택 작업의 명시된 키워드가 포함된 SIF 기록 건수와 사고유형을 별도 카드로 표시한다. 현장 위치를 선택하면 Open-Meteo 모델 예보와 작업 관련 확인 문구를 표시하고 기상청 특보현황으로 연결한다. 페이지를 아래로 읽은 뒤에도 맨 위로 돌아가는 고정 버튼을 제공한다.

사고 기록 경향은 전체 기록 기간을 기본값으로 두며 원하는 날짜 범위와 사고유형 부분 검색으로 좁힐 수 있다. 선택 범위의 요일·월·달력 계절·사고유형 원시 건수를 보여주며, 선택한 날짜 범위와 유형 검색을 담은 집계 CSV를 내려받는다. 다운로드에는 사고 원본 행이 포함되지 않는다.

현장 계획 상세는 위치·장비·작업책임자·계획 안전조치 중 비어 있는 항목을 날짜별로 모아 보여주고, 작업 상세로 바로 이동시킨다. 이는 자료 누락 확인이며 자동 위험도 판정은 아니다. 조치 목록에는 상태별 보기와 작업명·담당자·조치 ID 검색을 두고, 현재 필터 결과를 수식 실행 방지 처리를 적용한 CSV로 내보낸다. 지역 월별 챗봇 그래프는 해당 지역의 보유 기록 기간을 기준으로 만들고, 내일·모레 예보 답변에는 질문한 날짜를 표시한다. 사용자는 챗봇에서 대화와 검색용 작업 조건을 별도로 지울 수 있다.

기한이 지난 조치와 계획 변경으로 다시 확인할 조치 표기를 조치 화면·TBM 브리핑·챗봇의 남은 조치 답변에서 같은 기준으로 사용한다. 조치 완료나 재개 뒤 저장 사실도 화면에 바로 확인할 수 있다.

챗봇의 현장 답변에는 해당 작업일 화면, 선택한 미완료 조치 상세, TBM 브리핑으로 이동하는 동작을 붙여 답을 읽은 뒤 다시 메뉴에서 찾지 않아도 되게 한다.

이는 **단일 브라우저 세션의 파일럿**이다. 서버 영구 저장, 사용자·현장별 권한, 기상특보 자동 연동, 검증된 작업별 유사도·사례 연결, 작업자 수신·이해 확인, 모바일 현장 테스트는 아직 구현되지 않았다. 폭염 안내는 모델 체감온도에 따른 현장 확인 문구이며, 규정상 현장 측정이나 기상청 특보를 대신하지 않는다. 최신 [안전보건공단 폭염 예방수칙](https://www.kosha.or.kr/safety1team/tr/reference.do?articleNo=456837&attachNo=263892&mode=download)과 [고용노동부 한파 안전 안내](https://www.moel.go.kr/news/cardinfo/view.do?bbs_seq=20251200063)를 현장 조건에 맞춰 관리자·안전보건 전문가가 확인해야 한다. Open-Meteo 무료 API는 비상업적 평가용이므로 출시 운영에는 상업 사용권과 API 키가 필요하다. 샘플은 가상 현장이며 SIF 카드의 단어 포함 건수는 해당 작업의 사고 확률이 아니다. 실제 현장에 적용하기 전에 익명화한 계획서 양식과 자료 이용 범위, 안전보건 전문가 검토가 필요하다.

## 1. 제품이 해결할 일

관리자가 작업 시작 전 5분 안에 **확인된 작업계획에서 오늘 작업 자동 불러오기 → 해당 작업의 주요 사고 양상과 근거 → 현장 확인 사항 → 담당자별 미완료 조치 → TBM 공유**를 한 화면에서 파악하고 실행하게 한다. 일정에 없던 일회성 작업은 파일 첨부 또는 빠른 입력으로 추가한다. 작업 내용이 바뀌면 해당 작업의 주의사항을 다시 확인하고 변경 이력을 남긴다.

첫 출시 대상을 한 업종과 한 작업 흐름으로 좁히는 편이 검증에 유리하다. **제안 기준안은 건설 현장의 하루 작업 계획과 TBM**이며, 제조 현장은 다음 확장 대상으로 둔다. 업종 결정 전에는 데이터 구조와 화면 문구가 두 업종을 모두 수용하도록 설계한다.

한국산업안전보건공단의 [TBM 관련 운영 자료](https://oshri.kosha.or.kr/kosha/data/healthandsafetyf.do?articleNo=441256&attachNo=250367&mode=download)는 작업 전 위험요인과 조치의 공유, 최근 사고와 아차사고 활용, 관리자와 근로자의 참여를 다룬다. 실제 현장 적용과 법적 적합성은 출시 전에 안전보건 전문가가 [현행 위험성평가 지침](https://law.go.kr/LSW/admRulLsInfoP.do?admRulId=2052906&efYd=0)을 기준으로 검토한다.

## 2. 핵심 사용자 흐름

| 단계 | 관리자 행동 | 제품 결과 |
| --- | --- | --- |
| ⓪ 계획서 등록·확인 | 공정표·일일/주간 작업계획 또는 작업별 계획서를 업로드하고 추출된 작업·날짜·장소·장비를 검토 | 승인된 계획을 날짜별 작업 목록으로 저장, 출처 파일과 버전 연결 |
| ① 오늘 작업 확인 | 해당 날짜의 계획 작업을 자동 불러오고 변경·일회성 작업을 반영 | 오늘의 작업 목록과 누락·변경 항목 표시 |
| ② 위험 확인 | 작업 하나 선택 | 유사 사고의 유형별 **기록 건수**, 관련 사례, 안전 지침, 현장 자체 사고·아차사고 분리 표시 |
| ③ 조치 지정 | 현장에 맞는 예방 조치 선택·수정, 담당자와 완료 시각 지정 | 미확인·진행·확인 완료 상태와 조치 기한 표시 |
| ④ TBM 진행 | 핵심 위험과 조치를 작업자에게 공유, 참석·이해 확인 | 짧은 브리핑 화면, 인쇄·PDF, 기록 저장 |
| ⑤ 작업 중·종료 | 상황 변화, 아차사고, 조치 결과 입력 | 변경 이력과 다음 작업에 재사용할 현장 지식 축적 |

AI가 작성한 조치는 **초안**으로 표시하고 현장 관리자가 채택·수정·확인한다. 작업 허가나 안전 판정의 자동 승인은 범위에 넣지 않는다.

### 계획서에서 시작하는 첫 화면

현장에 승인된 계획이 없으면 상단에 `작업계획을 올려 오늘 작업을 시작하세요`와 **`계획서 업로드`**, **`일회성 작업 추가`**를 놓는다. 그 아래에는 전날부터 남은 조치와 인수인계 항목만 표시한다. 작업이 정말 없는 날은 `오늘 작업 없음`을 명시적으로 기록할 수 있게 해 미입력 상태와 구분한다. 계획에 오늘 날짜의 작업이 없으면 `계획에 등록된 오늘 작업 없음`으로 보여주고, 파일 누락·날짜 누락 가능성을 함께 확인하게 한다. 사고 그래프를 임의 작업으로 채우지 않는다.

일회성 작업의 빠른 등록은 **작업명·장소·시작 시간**만으로 시작한다. 예를 들어 `오전 9시 B동 2층 비계 해체`를 입력하면 작업·장소·시간을 분리해 **확인 가능한 입력칸**으로 보여준다. 장비, 인원, 협력업체, 보호구, 작업 단계는 해당 작업의 분석이나 TBM에 필요할 때 순서대로 확인한다. 맥락이 부족한 상태에서는 일반적인 사례만 보여주고 `장비를 입력하면 관련 사례를 좁힐 수 있습니다`처럼 부족한 정보를 구체적으로 알린다. [안전보건공단 TBM 자료](https://oshri.kosha.or.kr/kosha/data/healthandsafetyf.do?articleNo=441256&attachNo=250367&mode=download)도 작업 내용·범위·장소, 보호구, 신규 인력과 협력업체 작업을 사전에 파악하도록 안내한다.

계획 작업 또는 일회성 작업을 저장하면 해당 작업의 사고 양상·주의사항·조치 초안이 화면에 반영된다. 여러 작업이 있는 날에는 목록에서 작업을 바꾸면 차트와 문구가 함께 바뀐다. 전날과 같은 작업도 **오늘 달라진 장비·장소·인원·공법**을 먼저 확인한다. 외부 일정 연동은 실제 현장 시스템을 확인한 뒤 추가한다.

### 계획서 업로드 → 매일 갱신

1. **파일 받아들이기:** 현장에서 실제 쓰는 일일/주간 계획, 공정표, 작업별 계획서의 형식을 조사해 우선 지원 형식을 정한다. PDF·엑셀·CSV를 첫 후보로 두고, 스캔 PDF와 HWP/HWPX는 확보한 현장 양식에 따라 처리 범위를 결정한다.
2. **작업 추출·검토:** 작업명, 예정일·시간, 동/층/구역, 작업 단계, 장비, 인원, 협력업체, 계획된 안전조치를 추출한다. 화면에 **원문 위치와 추출값**을 나란히 보이고, 빠진 값·애매한 날짜·중복 작업을 관리자에게 확인받는다. 작업별 계획서에 수행 날짜가 없으면 일일/주간 일정과 연결하거나 날짜를 직접 지정한다. AI가 날짜를 지어내지 않는다.
3. **날짜별 작업 목록 저장:** 확인된 행만 현장 계획 버전과 함께 저장한다. 수정본 업로드 시 이전 버전과 작업 추가·삭제·시간·장소·장비 변화를 보여주고 확인 후 반영한다.
4. **매일 자동 구성:** 오늘 날짜에 해당하는 작업, 현장 위치·작업 시간에 맞는 기상 정보, 관련 사고 사례의 기록 건수, 현장 아차사고·미완료 조치를 모아 대시보드와 브리핑 초안을 생성한다. 계획서의 갱신 시각과 오늘 계획 확인 여부를 상단에 표시한다. 오래된 계획만 있으면 `오늘 작업 확인 필요`로 알린다.
5. **작업자 공유:** 관리자가 오늘의 핵심 위험과 조치를 검토한 뒤 읽기 쉬운 브리핑 카드로 확정한다. QR/링크, 인쇄·PDF 중 현장에 맞는 방식으로 공유하고 버전·공유 시각·대상을 기록한다. 이후 작업이 바뀌면 새 버전을 만들고 변경된 부분을 다시 전달한다. 협력업체에는 필요한 작업 범위만 보이게 한다.

안전보건공단의 [TBM 자료](https://oshri.kosha.or.kr/kosha/data/healthandsafetyf.do?articleNo=441256&attachNo=250367&mode=download)는 작업 일정, 작업 내용·장소·물량, 협력업체, 최근 사고, 날씨·계절 변화를 사전 준비와 공유 주제로 제시한다. [OSHA의 다수 사업주 현장 안내](https://www.osha.gov/safety-management/communication)도 원청과 협력업체 간 작업 위험·조치의 전달과 조정을 다룬다.

## 3. 정보 구조와 첫 화면

내비게이션: **오늘의 작업 · 작업 상세 · 조치 현황 · 현장 기록 · 근거 챗봇 · 데이터/설정**. 기존의 `현황 분석`, `사고 기록`, `자료 안내`, `근거 챗봇`은 사본에서 계속 볼 수 있고 새 제품의 내비게이션은 실제 업무 순서로 재구성한다.

```text
회색 작업 공간
  ┌────────────── 중앙의 흰색 대시보드 ──────────────────────────────────┐
  │ 왼쪽 메뉴 │ 오늘의 작업    현장 / 날짜 / 교대        데이터 갱신 시각 │
  │           │ 작업 N건 · 조치 미완료 M건 · TBM 대기 K건                 │
  │           │ ┌─ 작업 목록 ───────────┐ ┌─ 지금 확인할 조치 ───────┐ │
  │           │ │ 08:00 외벽 비계 설치   │ │ 추락 방지 설비 확인   담당 │ │
  │           │ │ 10:00 자재 양중        │ │ 신호수 배치 확인      담당 │ │
  │           │ └───────────────────────┘ └───────────────────────────┘ │
  │           │ 선택 작업: 단계 · 장비 · 장소 · 변경 사항                 │
  │           │ 유사 사례 사고유형별 건수  |  핵심 주의사항  | 근거 N건   │
  │           │ [조치 지정] [TBM 시작] [작업 변경 기록]                  │
  └──────────────────────────────────────────────────────────────────────┘
```

첫 화면의 우선순위는 **미완료 조치, 예정 작업, 해당 작업의 주의사항**이다. 차트는 결정에 필요한 범위에 놓는다. 같은 카드 안에 큰 그래프와 긴 문장을 억지로 넣지 않는다.

관리자가 첫 화면에서 바로 답을 얻어야 하는 질문은 네 가지다: **오늘 어디서 무슨 작업을 하는가? 시작 전에 무엇이 미확인인가? 비슷한 작업에서 어떤 사고가 있었는가? 지금 누가 어떤 조치를 해야 하는가?** 데스크톱 첫 화면 높이에서는 작업 목록, 미완료 조치, 선택 작업의 짧은 사고유형 그래프와 핵심 주의사항을 함께 볼 수 있게 배치한다. 상세 근거와 전체 이력은 선택 후 연다. [GOV.UK의 대시보드 지침](https://brand.design-system.service.gov.uk/data/dashboards/)처럼 정보의 위계가 명확해야 데이터가 많아도 핵심을 놓치지 않는다.

### 차트 설계

1. **유사 사례의 사고유형:** 선택 작업과 연결된 과거 사례의 유형별 건수를 정렬된 가로 막대로 표시한다. 막대 호버에는 건수, 적용 필터, 사례 1~2개, 원자료 시기를 보여준다. 점 장식과 항상 켜진 강조 박스는 쓰지 않는다.
2. **작업 단계별 사고 양상:** 단계별 누적 막대와 선택 상세를 연결한다. 한 막대의 바깥쪽만 둥글게 처리하고, 내부 구간은 맞닿게 그려 복잡한 라운딩을 없앤다.
3. **현장 자체 추이:** 현장이 실제 사고·아차사고 기록을 꾸준히 입력할 때만 월별 추이를 표시한다. 데이터가 없으면 관련 사례와 조치 현황을 보여준다. 모든 차트에는 기간, 표본 수, 출처, 결측 여부를 가까이 표기한다.

**과거 사례의 빈도는 오늘의 사고 확률이 아니다.** 작업 시간·노출 인원 등의 분모와 수집 범위가 없어 확률이나 현장 간 위험 순위를 만들 수 없다. 사례가 없을 때는 `기록 0건` 대신 `이 조건에서 확인된 사례 없음 / 수집 범위 확인`을 보여준다.

### 시각·접근성 원칙

- 기존 화면의 회색 캔버스와 중앙 정렬, 얇은 경계, Pretendard를 유지한다. 본문은 규칙적인 자간·행간과 충분한 카드 간격을 사용하고 굵은 글씨는 중요한 수치와 행동에 한정한다.
- 차콜·웜그레이를 기본으로, 한 가지 차분한 포인트 색을 선택 상태와 주요 동작에 사용한다. 주의 색은 **미완료 조치·기한 초과 같은 상태**에만 사용한다. 색만으로 상태를 전달하지 않고 텍스트와 아이콘을 병기한다.
- 표·차트는 키보드 이동, 명확한 포커스, 충분한 대비, 수치의 텍스트 대체 표시를 제공한다. 호버 상세는 화면 스타일에 맞는 커스텀 툴팁으로 제공하되 터치·키보드에서도 같은 내용을 볼 수 있어야 한다.
- 현장 태블릿에서는 작업 목록과 핵심 조치가 첫 화면에 보이고, 1열 레이아웃으로 자연스럽게 접히게 한다.

### 이동·조작의 마찰 줄이기

| 불편한 순간 | 화면 동작 |
| --- | --- |
| 아래까지 읽고 다시 위의 작업을 바꿔야 함 | 한 화면 이상 내려가면 `맨 위로` 버튼이 오른쪽 아래 나타난다. 누르면 상단으로 이동하고 제목/선택 작업에 키보드 초점이 돌아간다. 긴 상세 화면에는 `작업 정보 · 사고 양상 · 조치 · 근거` 바로가기와 현재 위치 표시도 둔다. |
| 스크롤 후 어느 현장·날짜·작업을 보고 있었는지 잊음 | 현장·날짜·선택 작업을 얇은 고정 막대에 유지한다. 좁은 화면에서는 날짜와 작업명만 남긴다. 고정 막대가 본문이나 키보드 초점을 가리지 않게 한다. |
| 차트에서 의미를 찾으려고 모든 막대에 마우스를 올려야 함 | 차트 제목 바로 아래에 `유사 사례에서 가장 많이 기록된 유형: 추락`처럼 실제 데이터에서 계산한 핵심 사실과 기준을 문장으로 표시한다. 호버는 추가 정보만 담고, 클릭·키보드·터치로 같은 상세를 연다. |
| 필터를 바꾼 뒤 결과가 왜 달라졌는지 모름 | 선택된 기간·작업·장비를 차트 위에 보이고 `필터 초기화`를 제공한다. 빈 결과는 사용한 조건과 다음 행동을 설명한다. |
| 여러 페이지를 오가다 입력을 잃음 | 작업 등록·조치 작성은 임시 저장과 명확한 저장 상태를 제공한다. 목록으로 돌아오면 필터, 선택 작업, 스크롤 위치가 유지된다. |
| 조치 완료를 실수로 누르거나 경고가 너무 많음 | 완료 뒤 짧은 `실행 취소`를 제공하고, 실제 업무를 멈춰야 할 항목만 강하게 표시한다. 상태 변화는 페이지 재탐색 없이 목록과 요약에 반영한다. |

`맨 위로`와 고정 막대는 [W3C의 키보드 초점 가림 방지 기준](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)을 함께 고려해 설계한다. 핵심 차트 정보는 툴팁에만 숨기지 않는다. [GOV.UK 차트 지침](https://brand.design-system.service.gov.uk/data/charts/)도 제목·단위·기간·출처와 핵심 설명을 차트 주변에 두도록 안내한다.

### 화면의 우선순위와 알림 규칙

첫 줄의 수치는 `오늘 작업`, `시작 전 확인 대기`, `기한 지난 조치`, `TBM 미완료`처럼 **오늘의 행동으로 이어지는 항목**을 쓴다. 완료율 같은 요약 수치는 필요한 분모와 맥락이 충분할 때만 보조 지표로 쓴다. 주의 문구는 `작업 → 이유 → 확인할 항목 → 담당자/기한` 순서로 한 줄 요약하고, 눌러서 바로 해당 조치로 이동하게 한다. 배너는 한 번에 가장 중요한 현장 전체 문제에만 사용한다. [GOV.UK 알림 지침](https://design-system.service.gov.uk/components/notification-banner/)은 배너 남용 시 사용자가 놓치기 쉬움을 설명한다.

### 현장에서 놓치기 쉬운 상황

- **동시 작업 간섭:** 같은 장소·시간에 양중 작업과 통행, 화기 작업과 가연물 취급처럼 작업이 겹치면 충돌 가능성을 표시한다. 자동 판정 대신 위치·시간·작업 유형의 일치 근거와 확인할 담당자를 보여준다.
- **작업 변경:** 장비, 장소, 인원, 공법, 일정이 바뀌면 해당 작업의 조치와 TBM 확인 상태를 다시 열어 재확인을 요구한다. 변경 전·후와 확인자를 기록한다.
- **교대 인수인계:** 전 교대의 미완료 조치와 새 교대의 시작 작업을 한 묶음으로 보여주고 인계·인수 확인을 남긴다.
- **정보 신선도:** 작업 계획이 갱신되지 않았거나 근거 자료의 기준 시점이 오래됐으면 갱신 시각과 확인 필요 상태를 표시한다. 정보가 없을 때 안전하다고 해석하게 만들지 않는다.
- **현장 참여:** 작업자나 반장이 아차사고·현장 변화·조치 미이행을 짧게 제보하면 관리자 확인 목록으로 이어진다. 과거 사고 건수와 별도로 조치 확인 지연, 미완료 조치 등 예방 활동 지표를 본다. [OSHA의 선행지표 안내](https://www.osha.gov/leading-indicators/)도 사고 발생 통계와 예방 활동 지표를 구분한다.

이 항목은 실무 가설이다. 실제 작업계획서와 현장 인터뷰에서 중요도·오탐·입력 부담을 검증해 첫 버전 범위를 정한다. 작업 변경과 비정형 작업의 위험 재확인은 [OSHA의 작업 위험 확인 지침](https://www.osha.gov/safety-management/hazard-identification)에서도 다룬다.

### 날씨·계절·요일 신호

**첫 출시 방향은 현장의 실제 기상 정보와 오늘 작업을 연결한 안내**다. 현장 위치, 작업 예정 시간, 실내·실외 여부, 작업 종류를 확인하고 [기상청 기상특보](https://www.weather.go.kr/w/special-report/overall.do)와 예보 갱신 시각을 가져온다. 폭염·호우·강풍·한파 등 중 **그 작업에 관련된 조건**이 있을 때만 작업 카드와 조치 목록에 짧게 표시한다. 여름·장마·겨울의 계절별 사전 점검은 작업 등록과 TBM 준비에 연결한다. [고용노동부의 2026년 폭염 대응 자료](https://moel.go.kr/policy/policydata/view.do?bbs_seq=20260500439)와 [안전보건공단의 장마철 건설현장 길잡이](https://www.kosha.or.kr/kosha/report/notice.do?articleNo=405193&attachNo=226135&mode=download)처럼 해당 시기·업종 자료를 근거로 삼되, 실제 적용 문구는 현장 전문가가 검토한다.

예시 문구의 구조: `B동 외부 양중 · 작업 시간에 강풍특보 예보 · 인양 계획과 장비 상태 재확인 · [담당자 지정]`. 메시지에는 **대상 작업, 기상 조건, 관측/예보 구분, 발표·갱신 시각, 출처, 지금 확인할 행동**이 들어간다. 작업 등록·시작 전 확인·기상 조건 변경 시점에 평가하고, 같은 안내는 반복하지 않다가 조건이 악화되거나 작업이 바뀌면 다시 표시한다. 기상 조건과 작업을 연결하는 기준 및 안내 문구는 현장 안전보건 전문가가 검토한다. 현장 자체 측정값과 예보가 다를 수 있으므로 관리자가 실제 상태를 확인하고 기록할 수 있게 한다. 기상 데이터가 지연·누락되면 `날씨 확인 불가`를 표시한다.

현장 CSV의 날짜로 요일·월·달력상 계절의 원시 건수는 보여준다. 이것만으로 특정 요일·계절 또는 날씨가 사고를 일으킨다고 판단하지 않는다. 강수·기온·특보의 실제 영향 분석에는 사고 시각에 맞춘 과거 현장 기상 관측, 작업 유형, 근로자 수·작업시간 같은 노출 정보가 필요하다. 관련 자료를 함께 모은 뒤에도 표본이 적거나 차이가 불확실하면 경고를 만들지 않는다. 검증된 패턴은 위험 확률처럼 표현하지 않고 출처와 비교 범위를 표시한다.

### 추가로 확인할 운영 조건

- **작업 허가와 선행 조건:** 현장의 기존 작업허가·점검 절차가 있다면 필요한 문서와 확인 담당자를 작업 카드에 연결한다. 대시보드가 허가를 자동 승인하지 않는다.
- **현장 네트워크 장애:** 아침 TBM 때 연결이 불안정해도 마지막으로 확인한 작업 계획의 시각을 볼 수 있는지, 기록은 어떻게 임시 보관·동기화할지 파일럿에서 확인한다.
- **다국어·전달 확인:** 작업자에게 공유한 핵심 위험과 조치를 짧은 언어·이미지로 전달하고 실제 이해 여부를 확인한다. [안전보건공단 TBM 자료](https://oshri.kosha.or.kr/kosha/data/healthandsafetyf.do?articleNo=441256&attachNo=250367&mode=download)는 신규·외국인 작업자와 이해 확인을 함께 다룬다.
- **권한과 개인정보:** 협력업체는 자기 작업에 필요한 범위만 보게 하고, 작업자 건강 정보처럼 민감한 입력은 수집 필요성을 별도로 검토한다.

## 4. 기능 우선순위

| 단계 | 기능 | 완료 기준 |
| --- | --- | --- |
| 첫 사용 가능 버전 | 확보한 현장 양식 1~2종의 계획서 업로드·추출 확인, 날짜별 자동 작업 목록, 일회성 작업/파일 추가, 작업별 사례·주의사항, 담당자별 조치, TBM 브리핑·작업자 공유, 출처·갱신 시각 | 계획서 한 번 등록 후 다음 작업일의 대시보드가 자동 구성되고, 관리자가 내용을 검토·공유할 수 있음 |
| 현장 파일럿 | 다양한 계획 양식·스캔본 처리, 수정본 비교, 현장 사고·아차사고 입력, 작업 변경 시 재확인, 현장별 기상 안내, 역할별 접근, 검색·필터, PDF/인쇄 | 1~2개 현장에서 실제 일일 업무에 사용 가능 |
| 확장 | 작업허가·EHS 연동, 다국어 작업자 안내, 사진 첨부, 승인된 외부 데이터 연계, 모바일 사용성 강화 | 현장 운영 체계와 연결되고 데이터가 중복 입력되지 않음 |

초기 입력은 **계획서 업로드를 기본**으로 하고, 일정에 없는 작업만 빠른 등록이나 챗봇 파일 첨부로 추가한다. 실제 현장 양식 1~2종을 확보해 추출·검토 화면을 먼저 검증한다. 업로드 내용은 날짜별 작업으로 저장되기 전 관리자가 확인한다.

## 5. 챗봇의 역할

챗봇은 독립 페이지로 유지한다. 작업 상세에는 `이 작업에 대해 질문` 진입점만 두고, 이동 시 선택된 작업·장비·장소를 질문 맥락으로 전달한다. 관리자가 매일 확인하는 작업·주의사항·그래프·조치는 질문을 입력하지 않아도 화면에서 읽고 실행할 수 있어야 한다. 챗봇은 조건이 복잡한 질문, 사례의 세부 설명, TBM 초안 작성에 집중한다.

| 질문 종류 | 처리 방식 | 응답 형태 |
| --- | --- | --- |
| “오늘 비계 작업 몇 건?” “미완료 조치?” | 권한 범위 내 구조화된 현장 데이터 조회 | 정확한 숫자와 적용 날짜·필터 |
| “이 작업에서 어떤 사고가 있었나?” | 이용 허락이 확인된 사례·지침 검색 | 2~3개 근거, 핵심 상황, 적용 가능성과 한계 |
| “TBM 문안 만들어 줘” | 현재 작업 정보와 확인한 근거로 초안 작성 | 관리자가 수정·확정할 수 있는 체크리스트 |
| 맥락이 부족하거나 근거가 약함 | 필요한 작업·장비·현장 조건을 짧게 질문 | 확인이 필요한 이유와 확인 가능한 자료 |

그래프 수치는 데이터 조회 코드가 계산한다. 챗봇은 출처, 문서 날짜, 적용 조건을 함께 제시하고 현장 상황과 다른 사례를 단정하지 않는다. 답변의 근거 연결과 숫자 일치, 질문 실패, 자료가 없는 경우를 출시 전 평가한다.

### 챗봇을 현장 도구로 만드는 기능

현재 앱은 지역·월별 CSV 질의와 문서 검색이 가능하지만 `현재 작업`을 챗봇 페이지에서 다시 입력해야 하고, 자료 종류·검색 방식을 사용자가 직접 고른다. 새 제품은 **선택 작업을 자동으로 이어받고**, 검색 기술 설정은 운영자 설정으로 옮긴다. 상단에는 `B동 외벽 비계 해체 · 09:00 · 장비 미입력`처럼 챗봇이 알고 있는 맥락을 보여주고 한 번에 수정하게 한다.

| 우선순위 | 기능 | 사용자가 얻는 결과 |
| --- | --- | --- |
| 첫 버전 | **오늘의 변경 요약** | 전날/직전 교대와 비교해 달라진 작업·장비·장소·인원과 미완료 조치를 3개 이내로 요약. 기상 연동 후 날씨 변화도 포함. 각 차이의 원본 필드로 이동 |
| 첫 버전 | **누락 후보 질문** | `장비가 비어 있습니다`, `같은 장소의 다른 작업이 있습니다`처럼 실제 입력에서 확인 가능한 누락·겹침을 질문. 답을 입력하면 해당 작업 카드가 갱신됨 |
| 첫 버전 | **그래프와 사례 설명 연결** | 막대·사고유형을 선택한 상태에서 `왜 이 유형을 보나요?`를 누르면 적용된 필터, 사례, 출처, 오늘 작업과의 공통점·차이를 설명 |
| 파일럿 | **답변을 조치 초안으로 전환** | 근거가 있는 예방 조치를 `담당자 지정` 가능한 초안으로 생성. 관리자가 수정·채택한 뒤에만 실제 조치에 등록 |
| 파일럿 | **TBM 핵심 요약과 전달 확인** | TBM에서 읽을 핵심 위험·현장 조치·확인 질문의 초안을 쉬운 문장으로 작성. 필요한 언어로 전달하고 관리자가 작업자 이해 여부를 기록 |
| 파일럿 | **교대 인계 요약** | 다음 교대에 남길 미완료 조치, 변경된 작업, 기상 변화와 해당 기록으로 바로 이동 |
| 파일럿 | **자료 간 불일치 발견** | 작업 계획·작업허가서·TBM 기록의 장소, 장비, 시간 등이 서로 다르면 원문 위치를 나란히 보여주고 관리자 확인을 요청 |
| 후속 검토 | **현장 제보 정리** | 작업자가 남긴 짧은 텍스트·음성·사진을 구조화된 아차사고/위험 제보 초안으로 정리. 작성자가 내용을 확인하고 민감 정보가 없는지 검토한 뒤 제출 |

**일회성 작업용 파일 첨부:** 챗봇에서 `이번 작업계획서 분석`을 선택해 파일을 붙이면, 작업명·장소·시간·장비·계획된 조치를 원문과 대조할 수 있는 카드로 추출한다. 필요한 조건 한두 가지를 확인한 뒤 관련 사고 사례, 기상 주의사항(연동 시), TBM 핵심 항목과 조치 초안을 보여준다. 이 분석은 임시 상태로 시작한다. 관리자가 **`오늘 작업에 추가`**를 누르고 추출값을 확인해야 정식 작업 목록과 작업자 브리핑에 들어간다. 필요하면 분석만 보고 종료할 수 있다. 파일의 접근 권한·보관 기간·삭제 방법을 현장 운영 정책에 맞춰 정한다.

챗봇 첫 화면에는 자유 입력창과 함께 **`오늘 달라진 점` · `이 작업의 유사 사고` · `TBM 문안` · `인계할 조치`** 바로가기를 기능 제공 범위에 맞춰 둔다. 변경·누락 후보는 대시보드 카드에도 자동으로 보여주고, 사용자는 챗봇에서 이유를 더 묻는다. 작업 맥락이 부족하면 긴 질문지를 띄우지 않고, 지금 답의 정확도를 가장 높일 한 가지 정보부터 묻는다. 답변은 `결론 한 줄 → 오늘 확인할 행동 → 왜 관련 있는지 → 근거와 기준일` 순서로 표시한다. 근거가 없거나 상충하면 그 상태를 알리고, 현장 안전관리자에게 질문과 자료를 전달할 수 있게 한다. [GOV.UK의 AI 서비스 지침](https://www.gov.uk/service-manual/technology/using-artificial-intelligence-ai-in-services)은 AI 답변의 한계와 사람에게 문의하는 경로를 사용자에게 알리도록 한다.

특히 **오늘의 변경 요약**은 작업 준비 시간을 줄일 가능성이 큰 차별화 기능이다. 예를 들어 이전 교대와 비교해 작업 장소와 장비가 바뀌었다면, 챗봇은 변경 사실·영향받는 조치·확인 담당자를 한 묶음으로 보여준다. 변경 감지는 저장된 필드 비교로 하고, AI는 그 결과를 설명한다. 중요한 조치의 완료·작업 허가·위험성평가 확정은 권한 있는 사람이 수행하며 확인 이력을 남긴다. 답변 품질 평가는 일반적인 문장 유창성보다 **출처 일치, 숫자 정확성, 빠진 조건, 잘못된 조치 제안**을 중심에 둔다. [NIST AI 위험관리 자료](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)도 역할별 감독과 평가·문서화를 다룬다.

## 6. 데이터 현실과 출시 전 확인 사항

현재 `C:\SANUP-P`의 작업 관련 SIF 사례 6,032건은 작업명·사고유형·위험요인·대책 검색에 도움이 된다. 별도 업종별 통계는 **2025-12-31 기준 연간 자료**이며 작업·지역·날짜별 실시간 데이터가 아니다. 기존 대시보드는 CSV를 넣지 않으면 **시연용 가상 기록**을 그린다. 새 제품의 운영 화면에는 가상 기록을 실제 수치처럼 표시하지 않는다.

현재 자료만으로 현장별 `오늘의 사고 건수`, `오늘의 사고 확률`, `제주도 작업의 위험률`을 계산할 수 없다. 현장 계획과 자체 기록을 수집하고, 외부 자료의 시점·단위·표본 범위를 화면에서 구분해야 한다. 공공 통계는 배경 정보로 사용하고, 작업별 화면에는 연결 가능한 사례와 현장 데이터만 노출한다.

외부 공개 전 **자료 사용권 확인이 필수**다. 프로젝트의 `C:\SANUP-P\docs\data_usage_rights.md`는 SIF 원자료의 공공누리 제3유형, 조사보고서와 KOSHA GUIDE PDF의 가공·재배포·외부 LLM 전송 범위 미확인을 기록한다. [공식 SIF 자료 페이지](https://www.data.go.kr/data/15140383/fileData.do)의 조건과 [공공누리 제3유형 안내](https://www.mcst.go.kr/site/s_open/kogl/koglType.jsp)를 다시 확인하고, 공개 제품에 적재할 자료·인용 형태·AI 전송 범위를 자료 소유 기관과 정리한다. 허용 범위가 확정되기 전 공개 버전에는 해당 원문·청크·색인을 넣지 않는다.

운영 기술은 현장 작업·조치·TBM 기록을 권한이 분리된 저장소에 두고, 통계 계산과 챗봇 검색을 분리한다. 현재 챗봇의 `C:\SANUP-P` 로컬 경로와 개인 API 설정은 배포 환경으로 이전해야 한다. 현장별 접근 제어, 수정 이력, 비밀키 보관, 백업·복구, 오류 모니터링이 출시 요건이다. Streamlit은 첫 파일럿 화면으로 활용하되 동시 사용자·권한·현장 입력의 사용성을 파일럿에서 확인한 뒤 운영 형태를 결정한다.

## 7. 진행 순서와 통과 기준

1. **현장 검증:** 관리자·반장·안전관리자 5명 이상에게 하루 작업 계획서와 TBM 방식을 확인한다. 실제 일일/주간 계획·작업별 계획서 양식과 주요 작업 분류를 확보한다. 문서에 날짜와 장소가 어느 수준까지 적히는지 확인하고 첫 지원 형식을 정한다.
2. **데이터·권리 정리:** 작업명 표준화, 사례 연결 기준, 출처·기간 표시, 자료 이용 범위를 확정한다. 작업별 검색 결과를 안전보건 실무자와 함께 검토한다.
3. **대화형 파일럿 구현:** 사본과 별도 코드에서 계획서 업로드·원문 대조·확인, 날짜별 오늘 작업 생성, 작업 상세 차트, 조치·TBM·작업자 공유, 일회성 파일 챗봇을 구현한다. 가상·실제 자료가 화면에서 명확히 구분되어야 한다.
4. **현장 파일럿:** 1~2개 현장에서 2~4주간 사용성을 확인한다. 주요 측정치는 추출된 작업·날짜·장소의 정확도, 누락 작업 수, 계획 수정 반영 시간, TBM 준비·공유 시간, 근거 확인 성공률, 조치 누락·기한 초과, 챗봇 출처 정확도다. 짧은 파일럿의 사고 건수 변화만으로 예방 효과를 주장하지 않는다.
5. **출시 점검:** 자료 이용권, 안전보건 전문가 검토, 현행 규정 검토, 현장별 접근 분리, 기록 보존·복구, 접근성, 운영 장애 대응을 확인한다.

사용성 테스트에는 실제 관리자의 하루 시나리오를 쓴다: `오늘 10시 양중 작업의 미완료 조치 찾기`, `겹치는 작업 확인하기`, `작업 장비 변경 후 다시 TBM 준비하기`, `차트의 근거 사례 확인 후 원래 작업으로 돌아오기`, `태블릿에서 하단 기록을 읽고 맨 위로 이동하기`. 각 과제의 성공 여부, 걸린 시간, 잘못 누른 횟수, 뒤로 가기·스크롤 반복, 챗봇 사용 없이 필요한 정보를 찾았는지를 기록한다.

첫 디자인 검수 기준은 다음과 같다: **① 데스크톱 첫 화면에서 오늘 작업·미완료 조치·선택 작업의 핵심 그래프/문장을 발견할 수 있음, ② 차트의 주요 의미는 호버·챗봇 없이 알 수 있음, ③ 목록으로 돌아올 때 작업·필터·위치가 유지됨, ④ 긴 화면에서 한 동작으로 상단으로 돌아감, ⑤ 태블릿과 확대 화면에서 내용이 겹치거나 가려지지 않음.** 현장 관리자 테스트에서는 이 과제에 걸린 시간과 성공률을 측정해 배치를 고친다.

## 8. 다음 설계 입력

**계획서 업로드를 주 입력으로, 일회성 작업 파일·빠른 등록을 보조 입력으로 사용**하는 방향을 채택한다. 아파트 건축 현장을 첫 설계 시나리오로 두되 실제 첫 파일럿 업종은 현장 자료를 보고 확정한다.

구현 전에는 개인정보·업체명을 가린 **실제 일일/주간 작업계획 1~2종**과 **일회성 작업계획서 1종**이 필요하다. 파일 형식, 날짜·작업·위치 표기, 계획 수정 방식이 확인되면 추출 필드와 업로드 검수 화면을 구체화할 수 있다.
