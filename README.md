# 산업재해 현황 대시보드

Streamlit으로 현장 작업계획을 확인하고 사고 기록을 분석하는 대시보드입니다. 기본 화면은 **오늘의 작업**입니다. 기존 사고 기록 화면은 `기존 현황` 메뉴에서 계속 볼 수 있습니다.

## 화면 구성

- **오늘의 작업:** 주간·일회성 작업계획서 엑셀 업로드 → 추출 내용과 원문 행 확인 → 계획 적용 → 날짜별 작업, 동시 작업, 시작 전 확인 항목 확인. 일회성 작업 빠른 추가, 현장 확인 기록, TBM 문안 다운로드, 선택 작업을 챗봇에 전달할 수 있습니다.
- **현황:** 배너, 핵심 지표의 월별 미니 그래프, 업종·유형·지역 인포그래픽, 재해정도 구성과 상세 차트
- **사고 기록:** 필터 결과의 날짜·업종·지역·사고유형·재해정도 검색, 표 확인, 현재 검색 결과 CSV 다운로드
- **데이터 안내:** 파일 전체의 범위와 형식 검사 결과, 집계 기준과 해석 시 주의사항
- **근거 챗봇:** 별도 페이지에서 현재 사고 CSV의 지역 기록과 월별 그래프를 조회하고, `C:\SANUP-P`의 SIF 사고사례·사고조사보고서·KOSHA GUIDE를 검색해 인용 번호와 원문 링크를 확인. 작업계획서 `.xlsx`에서 작업 하나를 골라 질문 맥락에 적용하거나 오늘의 작업 목록에 추가할 수 있습니다.

왼쪽 작업 메뉴에서 화면을 전환합니다. 상단의 재해정도 선택은 현황과 사고 기록에 함께 적용됩니다. 왼쪽 **조회 조건**에서 기간·업종·지역을 설정하고, **필터 초기화**로 전체 기록을 다시 볼 수 있습니다. 데이터 안내는 업로드한 파일 전체를 설명합니다.

### 작업계획서 시험 사용

`오늘의 작업`에서 **샘플 계획서 받기**를 누르고, 내려받은 `.xlsx`를 업로드한 다음 미리보기에서 원문 행과 누락 항목을 확인해 **이 계획 적용**을 누르세요. 샘플에는 2026년 10월 12–16일의 가상 작업 11건이 들어 있습니다. 실제 양식은 샘플과 같은 열 이름을 사용해야 합니다. 계획에 없는 작업은 `일회성 작업 빠르게 추가`에서 입력할 수 있습니다. 작업을 고른 뒤 실제 현장 확인 상태·확인자·확인 내용을 기록하면 화면의 미완료 수치가 바뀝니다. TBM 문안은 계획서 내용을 정리한 초안으로, 화면에서 수정한 문구를 내려받을 수 있습니다.

수정된 계획서를 다시 올리면 추가·변경·제외된 작업ID를 적용 전에 보여줍니다. 같은 현장에서 내용이 바뀌지 않은 작업의 현장 확인 기록은 유지하고, 바뀐 작업은 다시 미확인 상태로 돌립니다. 화면에서 추가한 일회성 작업은 같은 현장으로 수정본을 적용할 때 유지합니다.

현재 지원 범위는 `.xlsx`이며, 계획과 확인 기록은 **브라우저 세션에만** 남습니다. `세션 백업 · 복원`에서 JSON 파일로 직접 내려받고 다시 가져올 수 있습니다. 자동 백업이나 사용자별 권한 관리가 없으므로 운영 기록 저장 수단으로 사용하지 마세요. 백업 파일에는 현장명·업체명·담당자와 확인 내용이 들어 있으니 보관에 주의하세요. 업로드한 내용의 안전조치는 원문에 적힌 계획이지 현장 확인 결과가 아닙니다.

로컬 `C:\SANUP-P\data\personal\processed\source_01_sif_cases.parquet`가 있으면 선택 작업의 작업명·장비에서 찾은 **한 가지 키워드**가 포함된 건설업 SIF 사례의 사고유형별 기록 건수를 표시합니다. 그 파일을 이 저장소에 복사하거나 배포하지 않습니다. 키워드가 같은 기록의 집계일 뿐 작업별 사고 확률이나 위험 순위가 아닙니다. 자료가 없는 배포 환경에서는 사례 카드가 연결 안내로 바뀝니다. 날씨와 현장 자체 사고 통계는 아직 연결되지 않았습니다.

새 제품의 화면·데이터 설계는 [현장 관리자용 기획안](docs/field_manager_dashboard_plan.md)에 정리했습니다. 기존 화면의 사본은 [보관본](archive/dashboard_2026-10-03/SNAPSHOT.md)에 있습니다.

## 실행하기

PowerShell에서 프로젝트 폴더를 연 뒤 실행하세요.

```powershell
uv run streamlit run src/shining_chatbot/app.py
```

브라우저에서 표시된 로컬 주소(기본값 `http://localhost:8501`)를 여세요.

챗봇 페이지의 **지역·월별 질문**은 현황 페이지와 같은 사고 CSV를 사용합니다. CSV를 업로드하지 않으면 가상 샘플 데이터로 답하며, 샘플에는 제주 지역 기록이 없습니다. 지역 기록이 없다는 답변은 실제 지역 사고가 0건이라는 뜻이 아닙니다.

안전 사례·지침 질문은 로컬 `C:\SANUP-P` 프로젝트의 완성된 검색 색인과 `src/retriever.py`, `src/rag_chain.py`를 그 프로젝트의 `.venv`에서 실행합니다. 다른 위치에 있다면 `SANUP_P_ROOT` 환경 변수로 경로를 지정하세요. 의미 검색과 답변 생성에는 `SANUP-P`의 `.env`에 `OPENAI_API_KEY`가 필요합니다. 키가 없으면 문자 검색으로 근거 문서만 표시합니다. 색인·원본 자료·키를 이 저장소로 복사하지 않습니다.

또는 활성화된 가상환경에서 실행할 수 있습니다.

```powershell
streamlit run src/shining_chatbot/app.py
```

## CSV 형식

UTF-8 또는 CP949 인코딩 CSV를 업로드할 수 있습니다. 필수 열은 다음과 같습니다.

| 발생일 | 업종 | 지역 | 사고유형 | 재해정도 | 재해자수 | 휴업일수 |
| --- | --- | --- | --- | --- | ---: | ---: |
| 2026-09-15 | 제조업 | 경기 | 끼임 | 중상 | 1 | 45 |

`재해정도`는 `경상`, `중상`, `사망` 중 하나입니다. `재해자수`는 1 이상의 정수, `휴업일수`는 0 이상의 정수로 입력하세요. 화면에서 샘플 CSV를 내려받아 형식을 확인할 수 있습니다.

사고 건수는 기록 행 수, 재해자 수와 휴업일수는 각 열의 합계입니다. 사망자 수는 재해정도가 `사망`인 기록의 재해자수 합계입니다. 이 데이터에는 전체 근로자 수가 없어 재해율을 계산하지 않습니다.
