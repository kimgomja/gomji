# Safety Atlas · 현장 안전 운영 대시보드

Streamlit으로 현장 작업계획을 확인하고 사고 기록을 분석하는 대시보드입니다. 기본 화면은 **오늘의 작업**입니다. 기존 사고 기록 화면은 `기존 현황` 메뉴에서 계속 볼 수 있습니다.

## 화면 구성

- **오늘의 작업:** 주간·일회성 작업계획서 엑셀 업로드 → 추출 내용과 원문 행 확인 → 계획 적용 → 날짜별 작업, 동시 작업, 시작 전 확인 항목 확인. 일회성 작업 빠른 추가는 현재 선택한 작업일을 기본값으로 씁니다. 작업이 비어 있는 날은 계획표를 확인한 관리자 기록을 남길 수 있고, 그 날짜의 계획이 바뀌면 다시 확인하도록 표시합니다. 현장 확인 기록과 선택 작업의 챗봇 질문을 연결할 수 있으며, 빈 일정 날짜에도 예보와 연결한 사고 기록의 요일·월·계절 정보를 확인합니다.
- **조치 현황:** 선택 작업에 조치·담당자·기한을 등록하고 미완료·기한 지남·완료를 한눈에 봅니다. 완료 내용과 확인자를 남기고 다시 열 수 있습니다. 계획서의 해당 작업이 변경되면 완료했던 조치도 재확인 상태로 돌아갑니다.
- **TBM 브리핑:** 날짜별 작업·동시 작업·남은 조치와 연결한 현장 예보를 한 화면에서 확인하고 관리자 확인본을 HTML로 내려받아 인쇄하거나 PDF로 저장할 수 있습니다. 작업자 공유용 텍스트도 복사하거나 내려받을 수 있습니다. 작업별 현장 확인이나 변경된 조치의 재확인이 남아 있으면 확인본을 만들 수 없습니다. 확인 이후 계획·조치·검토 기록·예보 요약이나 해당 날짜의 계획 변경 이력이 바뀌면 확인본을 이전 내용으로 표시합니다. 실제 브리핑을 진행한 뒤 진행자·참석 인원·질문과 변경 사항을 별도 기록할 수 있습니다.
- **사고 기록 경향:** 관리 범위의 실제 사고 CSV를 연결해 요일·월·계절별 날짜 기준 기록 건수와 사고유형을 확인합니다. 연결한 범위와 날짜를 함께 표시하며, 오늘의 작업에도 같은 요일·월·계절 기록 건수를 작게 보여줍니다. 새 파일이나 기록 범위를 선택했을 때 적용 전임을 알려주며, 연결 해제 시 파일 선택 상태도 초기화합니다. 기록과 기간이 충분하고 특정 시기의 건수가 두드러질 때만 작업량·수집 범위를 확인하라는 검토 메시지를 보여줍니다. 원본 행이 들어가지 않은 집계 CSV를 내려받을 수 있습니다. 근로자 수·작업일수 분모가 없어 사고 확률이나 시기별 위험 순위로 표시하지 않습니다.
- **현황:** 배너, 핵심 지표의 월별 미니 그래프, 업종·유형·지역 인포그래픽, 재해정도 구성과 상세 차트
- **사고 기록:** 필터 결과의 날짜·업종·지역·사고유형·재해정도 검색, 표 확인, 현재 검색 결과 CSV 다운로드
- **데이터 안내:** 파일 전체의 범위와 형식 검사 결과, 집계 기준과 해석 시 주의사항
- **근거 챗봇:** 별도 페이지에서 현재 적용한 계획의 오늘 주의사항·선택일 작업·남은 조치·TBM 준비 상태·최근 계획 변경에 즉시 답하고, 연결한 현장의 오늘·내일·모레 예보도 별도로 보여줍니다. 현장 예보를 연결했다면 오늘 주의사항에도 반영합니다. 현재 사고 CSV의 지역 기록과 월별 그래프를 조회하고, `C:\SANUP-P`의 SIF 사고사례·사고조사보고서·KOSHA GUIDE를 검색해 인용 번호와 원문 링크를 확인합니다. 작업계획서 `.xlsx`에서 작업 하나를 골라 질문 맥락에 적용하거나 오늘의 작업 목록에 추가할 수 있습니다.

날씨별 분석 자료는 아직 없으므로 챗봇은 강수·기온·특보와 사고 건수의 관계를 추정하지 않고 필요한 데이터 항목을 안내합니다. 계절별 사고 기록은 사고일의 달력상 계절로 묶은 원시 건수만 답합니다. 오늘·내일·모레 예보는 현재 작업을 준비하기 위한 현장 안내이며 과거 사고 당시의 날씨 자료가 아닙니다.

왼쪽 작업 메뉴에서 화면을 전환합니다. 상단의 재해정도 선택은 현황과 사고 기록에 함께 적용됩니다. 왼쪽 **조회 조건**에서 기간·업종·지역을 설정하고, **필터 초기화**로 전체 기록을 다시 볼 수 있습니다. 데이터 안내는 업로드한 파일 전체를 설명합니다.

### 작업계획서 시험 사용

`오늘의 작업`에서 **샘플 계획서 받기**를 누르고, 내려받은 `.xlsx`를 업로드한 다음 미리보기에서 원문 행과 누락 항목을 확인해 **이 계획 적용**을 누르세요. 샘플에는 2026년 10월 12–16일의 가상 작업 11건이 들어 있습니다. 실제 양식의 `작업일자·시작시간·종료시간·작업장소·작업명`처럼 흔한 열 이름도 읽으며, 작업ID가 없으면 날짜·시간·장소·작업명에서 식별자를 만듭니다. 적용 전에 현장명과 제외된 행을 꼭 확인하세요. 계획에 없는 작업은 `일회성 작업 추가`에서 입력할 수 있습니다. 작업을 고른 뒤 실제 현장 확인 상태·확인자·확인 내용을 기록하면 화면의 미완료 수치가 바뀝니다. 작업자에게 공유할 내용은 `TBM 브리핑`에서 진행자·공유 대상을 기록하고 확인본으로 내려받으세요.

수정된 계획서를 다시 올리면 추가·변경·제외된 작업ID를 적용 전에 보여줍니다. 같은 현장에서 내용이 바뀌지 않은 작업의 현장 확인 기록은 유지하고, 바뀐 작업은 다시 미확인 상태로 돌립니다. 화면에서 추가한 일회성 작업은 같은 현장으로 수정본을 적용할 때 유지합니다.

현장명이 다른 계획서를 적용하거나 다른 현장의 백업을 복원하면 이전 현장의 조치·TBM·예보 위치·사고 CSV 연결·챗봇 맥락을 분리합니다. 새 현장의 데이터가 이전 현장의 확인본에 섞이지 않도록 합니다.

현재 지원 범위는 `.xlsx`이며, 계획·계획 변경 이력·계획표 확인·작업 확인·조치·TBM 확인·진행 이력·예보 위치는 **브라우저 세션에만** 남습니다. 날짜와 기록 시각은 한국 표준시(KST) 기준입니다. `기록 백업 · 복원`에서 JSON 파일로 직접 내려받고 다시 가져올 수 있습니다. 자동 백업이나 사용자별 권한 관리가 없으므로 운영 기록 저장 수단으로 사용하지 마세요. 백업 파일에는 현장명·업체명·담당자와 확인 내용이 들어 있으니 보관에 주의하세요. 업로드한 내용의 안전조치는 원문에 적힌 계획이지 현장 확인 결과가 아닙니다.

로컬 `C:\SANUP-P\data\personal\processed\source_01_sif_cases.parquet`가 있으면 선택 작업의 작업명·장비에서 찾은 **한 가지 키워드**가 포함된 건설업 SIF 사례의 사고유형별 기록 건수를 표시합니다. 그 파일을 이 저장소에 복사하거나 배포하지 않습니다. 키워드가 같은 기록의 집계일 뿐 작업별 사고 확률이나 위험 순위가 아닙니다. 자료가 없는 배포 환경에서는 사례 카드가 연결 안내로 바뀝니다. 현장 자체 사고 기록은 별도 CSV 업로드로 연결합니다.

현장 날씨는 [Open-Meteo 예보 API](https://open-meteo.com/en/docs)를 사용합니다. 위치를 선택한 현장에만 16일 범위의 모델 예보를 표시하며, 예보가 제공되지 않거나 연결이 실패하면 그 상태를 표시합니다. 비·강풍·한파와 고온 예보는 작업명과 모델 체감온도에 따른 **확인 알림**으로 안내합니다. 모델 예보에서 폭염 기준을 판정하지 않으며, 작업장 체감온도 측정과 최신 [안전보건공단 폭염 예방수칙](https://www.kosha.or.kr/safety1team/tr/reference.do?articleNo=456837&attachNo=263892&mode=download), [고용노동부 한파 안전 안내](https://www.moel.go.kr/news/cardinfo/view.do?bbs_seq=20251200063), [기상청 특보현황](https://www.weather.go.kr/w/weather/warning/status.do)을 확인해야 합니다. Open-Meteo 무료 API는 [비상업적 평가·시제품 용도](https://open-meteo.com/en/terms)이며, 상업 운영에는 제공사의 사용권이 필요합니다. 계약한 API 키를 `OPEN_METEO_API_KEY` 환경 변수로 설정하면 고객용 엔드포인트를 사용합니다.

기존 사고 기록 화면에는 최대 25MB CSV를 올릴 수 있습니다. 사고 기록 경향 화면에는 `발생일,사고유형` 두 열이 있는 실제 CSV를 올립니다(최대 5MB·10만 행). `사고일자,재해유형` 같은 열 이름도 받으며, 다른 열은 경향 집계에 사용하지 않습니다. 연결된 파일은 브라우저 세션에만 남고 JSON 작업 백업에는 포함되지 않으므로 원본 CSV를 별도로 보관하세요. 현재 파일 형식에는 사고 당시 날씨와 작업시간·근로자 수가 없어 날씨별 사고 경향이나 사고 발생률을 계산하지 않습니다.

새 제품의 화면·데이터 설계는 [현장 관리자용 기획안](docs/field_manager_dashboard_plan.md)에 정리했습니다. 기존 화면의 사본은 [보관본](archive/dashboard_2026-10-03/SNAPSHOT.md)에 있습니다.

## 실행하기

PowerShell에서 프로젝트 폴더를 연 뒤 실행하세요.

```powershell
uv run streamlit run src/shining_chatbot/app.py
```

브라우저에서 표시된 로컬 주소(기본값 `http://localhost:8501`)를 여세요.

챗봇 페이지의 **지역·월별 질문**은 현황 페이지와 같은 사고 CSV를 사용합니다. CSV를 업로드하지 않으면 가상 샘플 데이터로 답하며, 샘플에는 제주 지역 기록이 없습니다. 지역 기록이 없다는 답변은 실제 지역 사고가 0건이라는 뜻이 아닙니다.

안전 사례·지침 질문은 로컬 `C:\SANUP-P` 프로젝트의 완성된 검색 색인과 `src/retriever.py`, `src/rag_chain.py`를 그 프로젝트의 `.venv`에서 실행합니다. 다른 위치에 있다면 `SANUP_P_ROOT` 환경 변수로 경로를 지정하세요. 의미 검색과 답변 생성에는 `SANUP-P`의 `.env`에 `OPENAI_API_KEY`가 필요합니다. 키가 없으면 문자 검색으로 근거 문서만 표시합니다. 색인·원본 자료·키를 이 저장소로 복사하지 않습니다.

또는 활성화된 가상환경에서 실행할 수 있습니다.

```powershell
streamlit run src/shining_chatbot/app.py
```

## CSV 형식

UTF-8 또는 CP949 인코딩 CSV를 업로드할 수 있습니다. 필수 열은 다음과 같습니다.

| 발생일 | 업종 | 지역 | 사고유형 | 재해정도 | 재해자수 | 휴업일수 |
| --- | --- | --- | --- | --- | ---: | ---: |
| 2026-09-15 | 제조업 | 경기 | 끼임 | 중상 | 1 | 45 |

`재해정도`는 `경상`, `중상`, `사망` 중 하나입니다. `재해자수`는 1 이상의 정수, `휴업일수`는 0 이상의 정수로 입력하세요. 화면에서 샘플 CSV를 내려받아 형식을 확인할 수 있습니다.

사고 건수는 기록 행 수, 재해자 수와 휴업일수는 각 열의 합계입니다. 사망자 수는 재해정도가 `사망`인 기록의 재해자수 합계입니다. 이 데이터에는 전체 근로자 수가 없어 재해율을 계산하지 않습니다.
